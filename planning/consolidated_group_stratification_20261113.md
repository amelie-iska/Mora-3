# Consolidated group-stratified split implementation

Add component-constrained allocation to the existing data/splits.py rather than replacing historical stable-hash assignments. The component-count interface accepts exact integer row and metadata-stratum counts for already proven disjoint components, avoiding full graph payloads. A bounded native GraphRecord adapter uses the existing transitive leakage_groups function. Retain official fixed roles at component level; contradictory roles in one connected component refuse before assignment. Never split a component to match target percentages.

Use a deterministic, seed-bound greedy minimization of normalized squared deviation in overall rows and metadata-stratum counts. This is a heuristic balance objective, not an optimal allocation guarantee or a proof of unknown biological independence. Fixed groups are counted first. Unfixed groups are processed by decreasing relative stratum concentration, then size and a stable seeded hash. Report exact target/achieved denominators, empty partitions and component counts. No label values, feature fitting, thresholds or similarity calculations are inferred here.

The caller must preregister ratios/seed and establish the complete component graph, namespace/identity mapping, source rights and allowed strata. Existing frozen corpus splits are never automatically rewritten. A pure independent audit recomputes group disjointness and fixed-role preservation for the native wrapper. Synthetic tests do not qualify the81-million-view corpus. Full-corpus materialization and publication remain gated on actual scoped grouping/rights evidence.

Reference for the non-overlap versus balance tradeoff: scikit-learn StratifiedGroupKFold documentation, https://scikit-learn.org/stable/modules/generated/sklearn.model_selection.StratifiedGroupKFold.html. The implementation here is an explicit three-way, fixed-role, multilabel metadata-stratum allocator, not a reproduction of that cross-validator.
