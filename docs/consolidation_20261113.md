## Group-level stratification, not holdout rewriting

The opt-in allocator in `src/mora3/data/splits.py` accepts already established disjoint components and exact metadata-stratum counts. It preserves fixed official roles, rejects contradictory fixed roles within a component, and deterministically balances unfixed components with a declared objective and seed. It reports achieved versus requested denominators and infeasible/empty partitions. It is a heuristic, not an optimal-balance theorem.

The native wrapper recomputes transitive group membership and audits assignments independently. Existing stable-hash splitting is unchanged. The count-only interface is checked with a100-million-row synthetic aggregate without materializing those rows; that test is not a real100-million-row corpus claim.

The existing registered source roles above were **not** converted to a new80/10/10 partition. Train-only pretraining sources and official holdouts cannot be casually reassigned to make global percentages attractive. New unfrozen populations still require preregistered component-level stratification, source-appropriate strata and validation of the underlying biological relations.

## Publication and execution boundaries

GitHub source publication, a Hugging Face payload release and full training are separate outcomes. No private source data may be uploaded merely because this declared-key audit passes. A dataset release needs a source-specific redistribution review, complete current eligible coverage, exact native materialization/masks/schema and a card that distinguishes public-release content from locally retained components. A metadata-only staging repository is not a usable training dataset.

The full combined model/source release still requires genuine distinct same-snapshot construction/model attestations, complete operator/width/resource/recovery qualification, fixed target specifications and current executable route bindings. Historical N29 parameter counts are not automatically the final extended model count. The original training admission remains closed; this package performed **zero substantive training runs**.

The authorized maximum remains24 native μP proxy trials plus at most two ordinary approximately80M target runs. Real terminal outcomes, validation-selected hyperparameter application, two completed target checkpoints and heldout evaluations remain required. Extra few-step distillation and preference/comparison optimizer runs are not silently added beyond that cap.
