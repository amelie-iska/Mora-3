# Native Rfam full-window preparation qualification

Scope: exact original Rfam15.1 train-only source under the staged 29-head candidate and common snapshots. This is input/target preparation qualification, not evaluation, loss measurement or a substantive training run.

The original `RfamCampaignAdapter.prepare` verified and decoded a complete group-sidecar Parquet file for **every** single-original-row window. With 18,423 windows in each direction and two distinct source bindings, this repeated the same physical sidecar verification thousands of times. The isolated implementation now caches each SHA256-verified group sidecar once per source shard and adapter instance, guarded by device/inode/size/mtime/ctime identity on every access. It rejects an identity change instead of silently reloading, validates source boundaries, and uses the existing strict `_project_original_row` without changing native targets, conditions or evidence classes. Complete preparation additionally rehashes each sidecar after each terminal pass.

The implementation retains the current active-checkout correction: a prepared Rfam evaluator refuses a native owner whose source snapshot is different, before calling the original owner admission gate. No model admission checks are removed. The source-native `model_adapter_supported=false` disposition is unchanged and not treated as evidence of missing adapter code.

The isolated `rfam_native_full_preparation` executes native preparation on each actual train window for prediction and generation under both source identities, validates the count and original target positions, checks final cursor exhaustion, and compares the candidate and common source results. It does **not** call the prepared model objective, construct an optimizer, inspect heldout targets, run any training or reserve an existing campaign slot.

This change alters the executable adapter digest. The historical common-source rebind receipt and earlier native replay remain immutable historical evidence, **not** new operator approvals or usable launch pins. A future reviewed common release must bind the new exact executable identity, verify the remaining 62-route family and obtain independent source/model admission, operator, optimizer, recovery, resource and matched-validation evidence before counted training.

The current strict cap remains exactly 24 proxy slots plus at most two ordinary approximately80M target runs. Synthetic test fixtures never enter production campaign accounting.
